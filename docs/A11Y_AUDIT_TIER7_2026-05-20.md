## 3. Runtime axe-core extension

`apps/web/tests/e2e/a11y.spec.ts` already covers business routes (54 routes × 3 personas, WCAG 2.2 AA, zero-critical gate). Showcase routes are gated by `NEXT_PUBLIC_ENABLE_SHOWCASE=1` and don't require auth — they belong to a separate test group.

This audit ships a companion spec `apps/web/tests/e2e/showcase-a11y.spec.ts` that:

1. Asserts `NEXT_PUBLIC_ENABLE_SHOWCASE=1` is set in test env.
2. Iterates all 18 showcase routes without storageState (anonymous browser).
3. Runs the same `AxeBuilder` ruleset (`wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22a, wcag22aa`) as the business spec.
4. Same zero-critical gate.
5. Persists JSON output to `test-results/showcase-a11y-audit/<route>.json` for downstream reporting.

Running the spec is **not part of brand v1 closure** (requires `pnpm dev` + Playwright environment). It's the recipe to verify the static audit when an axe pass is needed (CI, release gate).

## 4. Outstanding TODOs (post-Tier-7)

Items deliberately deferred — not blockers for brand v1 tag:

1. **Skip-link**: no `<a href="#main">Skip to main content</a>` injected at the top of any showcase page. Best practice for keyboard users to jump past the header. Should be added to `apps/web/src/app/showcase/layout.tsx` showcase chrome. Effort: ~15min.
2. **User menu dropdown**: `DashboardHeader` user menu currently opens nothing (cosmetic only in showcase). Real implementation in `apps/web/src/app/(authenticated)/layout.tsx` uses Radix `DropdownMenu`. Showcase parity: TBD per UXIX-0002 ratification.
3. **Lang switcher dropdown**: same as user menu — cosmetic in showcase.
4. **Favicon set generation** (from UXIX-0007 D Y-accent): 7 sizes from `HeuresysMark`. Effort: ~30min.
5. **Social media kit** (from UXIX-0007 D): OG image + Twitter card + LinkedIn banner. Effort: ~1h.
6. **Axe runtime pass**: actually run the new `showcase-a11y.spec.ts` in CI and pin the audit JSONs as artifacts. Effort: ~30min (env wiring + CI integration).
7. **UXIX-0002 / UXIX-0003 / UXIX-0004 ratification**: header / footer / sidebar composition ADRs are still `Proposed` in the register. Now that the canonical primitives are in production (`DashboardHeader` / `DashboardFooter` / `DashboardSidebar` from `@heuresys/ui` consumed by 5+ showcase pages), the ratification can mirror the UXIX-0005/0006/0007 pattern (de-facto + Accepted).
