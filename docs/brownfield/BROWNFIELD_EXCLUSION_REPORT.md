### C12 — SAP raw HR (2 EXCLUDE tables, DGOV)

> **Rule:** Raw SAP HR table dumps containing direct PII or payroll runtime data are out of scope (I8). SAP integration is a separate, post‑MVP design.

| Table | Why |
|-------|-----|
| `pa0167` | SAP Health Plans (medical/dental/vision) — also C14 medical |
| `pcl2` | SAP Payroll Cluster 2 — payroll calculation results |

> **Important scope clarification: EXCLUDE (2) vs REFERENCE_ONLY (≈ 93) for the SAP HR cluster.**
>
> The legacy DGOV domain contains a much larger **SAP HR cluster** (≈ 95 tables in total, see `BROWNFIELD_TABLE_CLASSIFICATION_REPORT.md` §3.12.1 breakdown). Of those:
>
> - **2 tables are EXCLUDE** (this category C12): `pa0167` and `pcl2` — they carry direct PII (health plans) or payroll runtime values.
> - **≈ 93 tables are REFERENCE_ONLY** (in `BROWNFIELD_TABLE_CLASSIFICATION_REPORT.md` §3.12 DGOV bucket): SAP HR structural / configuration cluster (`hrp10xx` position relationships, `pa2xxx` personnel actions, `pa9xxx`, `pb0xxx`, `pb4xxx`, `pcl1/3/4/5`, `ext_pa*`, `ext_hrp*`, and the SAP T‑configuration tables `t001p`, `t005*`, `t500*`, `t510*`, `t512w`, `t513`, `t527x`, `t528b`, `t529*`, `t549*`, `t5ubp`, `t771q`). They are not EXCLUDE because they don't directly carry PII or payroll runtime; they're not IMPORT/TRANSFORM because the new platform doesn't implement SAP HR integration in MVP scope.
>
> If a future ADR promotes SAP HR integration into scope, the ≈ 93 REFERENCE_ONLY SAP tables become candidates for IMPORT/TRANSFORM via the promotion process (`BROWNFIELD_TABLE_CLASSIFICATION_REPORT.md` §6). The 2 EXCLUDE rows (`pa0167`, `pcl2`) remain EXCLUDE regardless, because they fall under I8 (medical + payroll) which is a hard scope boundary independent of SAP integration status.

## 4. Column‑Level Filters (apply across all TRANSFORM imports)

Even on TRANSFORM tables, the following column patterns are stripped during transformation (see `BROWNFIELD_TABLE_CLASSIFICATION_REPORT.md` §4.2):

```text
EXCLUDE_COLUMNS:
  _fiscal_code         → strip (Italian PII)
  _codice_fiscale      → strip
  _ssn                 → strip
  _passport            → strip
  _passport_no         → strip
  _iban                → strip
  _bank_account        → strip
  _email_personal      → strip (allow _email_work)
  _phone_personal      → strip (allow _phone_work)
  _date_of_birth       → strip (only an is_adult boolean ever)
  _birth_date          → strip
  _dob                 → strip
  _health_*            → strip (and exclude the table)
  _medical_*           → strip (and exclude the table)
  _disability_*        → strip
  _salary_*            → strip (band only)
  _pay_*               → strip
  _compensation_amount → strip (band only)
```

A column flagged for strip whose absence breaks a NOT NULL constraint in the target invalidates the row (row dropped with `validation_status = ROW_DROPPED_COLUMN_FILTER`).
