## 0. Conventions

### 0.1 Schemas

| Schema | Role | Owns |
|--------|------|------|
| `sys` | **Canonical application schema.** Every target business table lives here. | All `sys.sys_<plural>` tables, the PIP view, validation views. |
| `staging` | Temporary candidate records before validation/approval. | Per‑run staging tables (truncated between runs). |
| `brownfield` | Mirror of legacy DBMS metadata + transformation buffers. | Source registry, table/column metadata, candidate buffers. |
| `audit` | Import logs, validation evidence, lineage operational logs. | `audit.import_runs`, `audit.validation_results`, etc. |

> The schema policy applies to every deliverable. Canonical data lives **only** in `sys`.

### 0.2 Naming rules

- Plural lowercase snake_case: `sys.sys_tenancies`, `sys.sys_user_position_assignments`.
- Always prefixed `sys.sys_` (the schema and the table both carry `sys` — explicit + idiomatic for this project).
- Columns:
  - In `sys.sys_users`, every column uses the `user_` prefix (e.g. `user_id`, `user_tenant_id`, `user_email`, `user_display_name`). Never `usr_`.
  - In other tables, columns are descriptive (`position_id`, `skill_id`, etc.).
- Surrogate PKs: `uuid` generated by `gen_random_uuid()` (pgcrypto) or `uuid_generate_v4()` (uuid‑ossp).
- Natural keys exist where idempotency demands it (e.g. `tenant_code` unique, `position_code` unique within tenant).
- Foreign keys: `<table>_<col>_fkey`; indexes: `<table>_<col>_idx`; unique: `<table>_<col>_uq`.

### 0.3 Idempotency contract

Every table is created with `CREATE TABLE IF NOT EXISTS`. Every column added later uses `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`. Seed inserts use `ON CONFLICT (<natural_key>) DO NOTHING` (or `DO UPDATE SET` where evolution is intended).

### 0.4 Tenant‑aware tables

Most `sys.sys_*` tables carry `<table_singular>_tenant_id uuid NOT NULL REFERENCES sys.sys_tenancies(tenant_id) ON DELETE RESTRICT` and an index on it. Exceptions are listed explicitly in each section.

### 0.5 Audit columns (default on every canonical table unless noted)

```sql
created_at  timestamptz NOT NULL DEFAULT now(),
created_by  uuid REFERENCES sys.sys_users(user_id) ON DELETE SET NULL,
updated_at  timestamptz NOT NULL DEFAULT now(),
updated_by  uuid REFERENCES sys.sys_users(user_id) ON DELETE SET NULL
```

A trigger `sys_set_updated_at()` updates `updated_at` on UPDATE. Defined once in 000002 and reused via `CREATE TRIGGER ... ON ... EXECUTE FUNCTION sys_set_updated_at()`.

### 0.6 Categorical fields convention

For every field that holds one of a fixed set of string codes (`user_type`, `user_status`, `position_criticality`, `user_position_assignment_kind`, `auth_login_event_type`, `notification_type`, `notification_priority`, `notification_status`, etc.):

- Storage: `varchar(N)` (typically 32 or 64).
- Constraint: explicit `CHECK (col IN ('VALUE_1', 'VALUE_2', ...))` declared in the migration that creates the column.
- Naming: `<table>_<col>_check` (idempotent via `ALTER TABLE ... DROP CONSTRAINT IF EXISTS ... ; ALTER TABLE ... ADD CONSTRAINT ...`).
- Evolution: adding a new value = drop the constraint + recreate with the extended list, in one migration file. **No** PostgreSQL `ENUM` type is used (avoids the `ALTER TYPE ADD VALUE` rigidity, simplifies introspection, makes Drizzle introspection trivial).
- Default value: declared inline (e.g. `user_status varchar(32) NOT NULL DEFAULT 'ACTIVE'`).

Example template:

```sql
ALTER TABLE sys.sys_users
  ADD COLUMN IF NOT EXISTS user_status varchar(32) NOT NULL DEFAULT 'ACTIVE';
ALTER TABLE sys.sys_users
  DROP CONSTRAINT IF EXISTS sys_users_user_status_check;
ALTER TABLE sys.sys_users
  ADD CONSTRAINT sys_users_user_status_check
  CHECK (user_status IN ('ACTIVE', 'INACTIVE', 'SUSPENDED', 'PENDING_VERIFICATION', 'DEACTIVATED'));
```

Where a categorical set is shared across multiple tables (e.g. validation_status: PENDING / PASSED / FAILED / WARNING), a small lookup table (`sys.sys_<concept>_catalog`) may be used instead of repeating the CHECK; the choice is per‑case and documented in the migration.

## 1. Foundation (Migrations 000001‑000006)

### 1.1 `sys.sys_tenancies`

Central tenancy registry. PK for the whole tenant‑aware graph.

```sql
CREATE TABLE IF NOT EXISTS sys.sys_tenancies (
  tenant_id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_code          varchar(64) NOT NULL,
  tenant_name          varchar(255) NOT NULL,
  tenant_legal_name    varchar(255),
  tenant_country_code  char(2),
  tenant_industry_code varchar(64),
  tenant_size_band     varchar(32),
  tenant_status        varchar(32) NOT NULL DEFAULT 'ACTIVE',
  tenant_metadata      jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at           timestamptz NOT NULL DEFAULT now(),
  updated_at           timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS sys_tenancies_tenant_code_uq ON sys.sys_tenancies(tenant_code);
CREATE INDEX IF NOT EXISTS sys_tenancies_status_idx ON sys.sys_tenancies(tenant_status);
```

- **Idempotency:** `tenant_code` is the natural key.
- **No `created_by`/`updated_by`** here — bootstrap inserts predate the existence of users.

### 1.2 `sys.sys_users`

Platform person/account anchor — **never** the full Core HR dossier. No passwords, no payroll, no benefits.

```sql
CREATE TABLE IF NOT EXISTS sys.sys_users (
  user_id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_tenant_id       uuid NOT NULL REFERENCES sys.sys_tenancies(tenant_id) ON DELETE RESTRICT,
  user_external_code   varchar(128),               -- HR system identifier, optional
  user_email           varchar(320) NOT NULL,
  user_display_name    varchar(255) NOT NULL,
  user_first_name      varchar(128),
  user_last_name       varchar(128),
  user_status          varchar(32) NOT NULL DEFAULT 'ACTIVE',
  user_type            varchar(32) NOT NULL DEFAULT 'STANDARD',  -- STANDARD | SYNTHETIC_REFERENCE | SERVICE
  user_is_synthetic    boolean NOT NULL DEFAULT false,
  user_locale          varchar(16),
  user_timezone        varchar(64),
  user_metadata        jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at           timestamptz NOT NULL DEFAULT now(),
  updated_at           timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS sys_users_tenant_email_uq ON sys.sys_users(user_tenant_id, lower(user_email));
CREATE INDEX IF NOT EXISTS sys_users_tenant_status_idx ON sys.sys_users(user_tenant_id, user_status);
```

- FK `user_tenant_id → sys_tenancies.tenant_id` is the **canonical tenant linkage**.
- `(user_tenant_id, lower(user_email))` is unique — tenant‑scoped email uniqueness.
- `user_is_synthetic = true` + `user_type = SYNTHETIC_REFERENCE` marks dev/test reference data.

### 1.5 Notifications & Inbox (migration 000006b — new, ADR‑0011 ESS)

Inbox notifications feed `/me/inbox` (ESS) and any future admin notification surface. Tenant‑aware, user‑scoped, time‑bounded (expirable).

```sql
CREATE TABLE IF NOT EXISTS sys.sys_inbox_notifications (
  notification_id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  notification_tenant_id     uuid NOT NULL REFERENCES sys.sys_tenancies(tenant_id) ON DELETE CASCADE,
  notification_user_id       uuid NOT NULL REFERENCES sys.sys_users(user_id) ON DELETE CASCADE,
  notification_type          varchar(64) NOT NULL,        -- TRAINING_DEADLINE | ASSESSMENT_REQUEST | MANAGER_FEEDBACK_READY | CAREER_TARGET_STATUS | GAP_CLOSURE_DUE | SYSTEM
  notification_subject       varchar(255) NOT NULL,
  notification_body          text,
  notification_action_url    text,                        -- deep link e.g. /me/learning/123 or /me/career
  notification_resource_type varchar(64),                 -- POSITION | LEARNING_MODULE | ASSESSMENT | CAREER_TARGET | KPI | SKILL
  notification_resource_id   uuid,                        -- polymorphic reference; FK enforcement deferred to API layer
  notification_priority      varchar(32) NOT NULL DEFAULT 'INFO',  -- INFO | MEDIUM | HIGH | CRITICAL
  notification_status        varchar(32) NOT NULL DEFAULT 'UNREAD', -- UNREAD | READ | DISMISSED | ARCHIVED
  notification_read_at       timestamptz,
  notification_dismissed_at  timestamptz,
  notification_expires_at    timestamptz,                  -- optional; renderer hides expired by default
  created_at                 timestamptz NOT NULL DEFAULT now(),
  created_by                 uuid REFERENCES sys.sys_users(user_id) ON DELETE SET NULL  -- NULL = system-generated
);
CREATE INDEX IF NOT EXISTS sys_inbox_user_unread_idx
  ON sys.sys_inbox_notifications(notification_user_id, created_at DESC)
  WHERE notification_status = 'UNREAD';
CREATE INDEX IF NOT EXISTS sys_inbox_tenant_user_created_idx
  ON sys.sys_inbox_notifications(notification_tenant_id, notification_user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS sys_inbox_resource_idx
  ON sys.sys_inbox_notifications(notification_resource_type, notification_resource_id)
  WHERE notification_resource_id IS NOT NULL;
```

- **Idempotency:** combination `(tenant_id, user_id, type, resource_id, created_at)` is *not* unique — same notification type may legitimately fire multiple times for the same resource (e.g. training deadline reminder at 7d, 3d, 1d). Systems that produce notifications should embed a `notification_dedup_key` in the `notification_body` JSON if dedup is needed.
- **Lifecycle:** UNREAD → READ (user opens) → DISMISSED (user dismisses) → ARCHIVED (auto‑archived after expiry). Hard delete only after `notification_expires_at + 90 days` via scheduled job (post‑MVP).
- **Polymorphic FK:** `(notification_resource_type, notification_resource_id)` is not a single DB FK. The application layer enforces consistency; a validation view (`sys.v_inbox_resource_consistency` in 000023) flags broken references.

## 4. Position, Assignment, Intelligence Profile (Migrations 000011‑000012)

### 4.1 `sys.sys_positions` (the spine)

```sql
CREATE TABLE IF NOT EXISTS sys.sys_positions (
  position_id                       uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  position_tenant_id                uuid NOT NULL REFERENCES sys.sys_tenancies(tenant_id) ON DELETE RESTRICT,
  position_code                     varchar(128) NOT NULL,
  position_title                    varchar(255) NOT NULL,
  position_organization_unit_id     uuid REFERENCES sys.sys_organization_units(organization_unit_id) ON DELETE SET NULL,
  position_job_role_id              uuid REFERENCES sys.sys_job_roles(job_role_id) ON DELETE SET NULL,
  position_reports_to_position_id   uuid REFERENCES sys.sys_positions(position_id) ON DELETE SET NULL,
  position_owner_user_id            uuid REFERENCES sys.sys_users(user_id) ON DELETE SET NULL,
  position_esco_occupation_uri      text,
  position_criticality              varchar(32),                    -- CRITICAL | HIGH | MEDIUM | LOW
  position_economic_weight          numeric(8,4),                   -- normalized [0..1]
  position_is_active                boolean NOT NULL DEFAULT true,
  position_effective_from           date NOT NULL DEFAULT current_date,
  position_effective_to             date,
  position_metadata                 jsonb NOT NULL DEFAULT '{}'::jsonb,
  position_ai_hints                 jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at                        timestamptz NOT NULL DEFAULT now(),
  updated_at                        timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS sys_positions_tenant_code_uq ON sys.sys_positions(position_tenant_id, position_code);
CREATE INDEX IF NOT EXISTS sys_positions_org_unit_idx ON sys.sys_positions(position_organization_unit_id);
CREATE INDEX IF NOT EXISTS sys_positions_job_role_idx ON sys.sys_positions(position_job_role_id);
CREATE INDEX IF NOT EXISTS sys_positions_owner_idx ON sys.sys_positions(position_owner_user_id);
```

- **`position_owner_user_id`** is the owner (accountable for the position's existence/requirements). **Different from incumbent** (see §4.2).
- `position_ai_hints` JSONB: free‑form AI suggestions (e.g. proposed skills not yet in catalog). Per ADR‑0008 this is the **only** legitimate use of JSONB on this table.

### 4.2 `sys.sys_user_position_assignments`

Bridge table for the user × position relationship over time.

```sql
CREATE TABLE IF NOT EXISTS sys.sys_user_position_assignments (
  user_position_assignment_id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_position_assignment_tenant_id    uuid NOT NULL REFERENCES sys.sys_tenancies(tenant_id) ON DELETE RESTRICT,
  user_position_assignment_user_id      uuid NOT NULL REFERENCES sys.sys_users(user_id) ON DELETE RESTRICT,
  user_position_assignment_position_id  uuid NOT NULL REFERENCES sys.sys_positions(position_id) ON DELETE RESTRICT,
  user_position_assignment_kind         varchar(32) NOT NULL,    -- PRIMARY | SECONDARY | INTERIM | ACTING
  user_position_assignment_fte          numeric(4,3) NOT NULL DEFAULT 1.000,  -- [0..1] full‑time equivalent
  user_position_assignment_start_date   date NOT NULL,
  user_position_assignment_end_date     date,
  user_position_assignment_status       varchar(32) NOT NULL DEFAULT 'ACTIVE',
  user_position_assignment_notes        text,
  created_at                            timestamptz NOT NULL DEFAULT now(),
  updated_at                            timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS sys_upa_user_idx ON sys.sys_user_position_assignments(user_position_assignment_user_id);
CREATE INDEX IF NOT EXISTS sys_upa_position_idx ON sys.sys_user_position_assignments(user_position_assignment_position_id);
CREATE INDEX IF NOT EXISTS sys_upa_tenant_status_idx ON sys.sys_user_position_assignments(user_position_assignment_tenant_id, user_position_assignment_status);
CREATE UNIQUE INDEX IF NOT EXISTS sys_upa_one_primary_active_per_user
  ON sys.sys_user_position_assignments(user_position_assignment_user_id)
  WHERE user_position_assignment_kind = 'PRIMARY' AND user_position_assignment_status = 'ACTIVE';
```

- **Partial unique index** enforces: a user can have at most one ACTIVE PRIMARY assignment at a time.
- Historical rows are kept indefinitely (status = `ENDED`).
- `user_position_assignment_kind = INTERIM | ACTING` allows temporary coverage without disturbing the primary.

### 4.4 `sys.sys_position_intelligence_profiles_v` (VIEW)

Per ADR‑0008, PIP is a **view** that aggregates the base tables, **not** a stored JSONB blob.

```sql
CREATE OR REPLACE VIEW sys.sys_position_intelligence_profiles_v AS
SELECT
  p.position_id,
  p.position_tenant_id,
  p.position_code,
  p.position_title,
  p.position_organization_unit_id,
  p.position_job_role_id,
  p.position_owner_user_id,
  p.position_esco_occupation_uri,
  p.position_criticality,
  p.position_economic_weight,
  (SELECT jsonb_agg(jsonb_build_object(
            'skill_id', psr.skill_id,
            'required_proficiency', psr.required_proficiency,
            'weight', psr.weight,
            'criticality', psr.criticality))
   FROM sys.sys_position_skill_requirements psr
   WHERE psr.position_id = p.position_id) AS required_skills,
  (SELECT jsonb_agg(jsonb_build_object(
            'kpi_definition_id', pkr.kpi_definition_id,
            'target_template', pkr.target_template,
            'weight', pkr.weight))
   FROM sys.sys_position_kpi_requirements pkr
   WHERE pkr.position_id = p.position_id) AS required_kpis,
  (SELECT jsonb_agg(jsonb_build_object(
            'learning_path_id', plr.learning_path_id,
            'mandatory', plr.is_mandatory,
            'deadline_rule', plr.deadline_rule))
   FROM sys.sys_position_learning_requirements plr
   WHERE plr.position_id = p.position_id) AS required_learning_paths,
  (SELECT jsonb_agg(jsonb_build_object('career_path_id', pcp.career_path_id))
   FROM sys.sys_position_career_paths pcp
   WHERE pcp.position_id = p.position_id) AS career_paths,
  (SELECT row_to_json(pcp2) FROM sys.sys_position_compensation_profiles pcp2
   WHERE pcp2.position_id = p.position_id LIMIT 1) AS compensation_profile,
  (SELECT row_to_json(psrr) FROM sys.sys_position_succession_relevance psrr
   WHERE psrr.position_id = p.position_id LIMIT 1) AS succession_relevance,
  p.position_ai_hints,
  p.updated_at
FROM sys.sys_positions p;
```

> The view is plain (re‑queried each access). If profiling shows hot paths, it can be promoted to `MATERIALIZED VIEW` in a non‑breaking change (add concurrent refresh in 000023 or post‑MVP).

### 13.1 `audit.user_self_service_actions` — DDL

```sql
CREATE TABLE IF NOT EXISTS audit.user_self_service_actions (
  action_id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  action_user_id         uuid NOT NULL REFERENCES sys.sys_users(user_id) ON DELETE RESTRICT,
  action_tenant_id       uuid NOT NULL REFERENCES sys.sys_tenancies(tenant_id) ON DELETE RESTRICT,
  action_type            varchar(64) NOT NULL,            -- PROFILE_UPDATE | SKILL_SELF_ASSESS | LEARNING_ENROLL | CAREER_TARGET_REQUEST | CERT_UPLOAD | DOC_UPLOAD | INBOX_MARK_READ
  action_resource_type   varchar(64),                     -- e.g. SKILL, LEARNING_MODULE, POSITION, CERTIFICATION
  action_resource_id     uuid,                            -- ID of the affected resource (if scalar; null if mutation is non-resource e.g. profile)
  action_payload_summary jsonb NOT NULL DEFAULT '{}'::jsonb,  -- bounded summary of mutation input; full body deliberately NOT stored (privacy + size)
  action_ip              inet,
  action_user_agent      text,
  created_at             timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS audit_ussa_user_idx       ON audit.user_self_service_actions(action_user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS audit_ussa_tenant_idx     ON audit.user_self_service_actions(action_tenant_id, created_at DESC);
CREATE INDEX IF NOT EXISTS audit_ussa_type_idx       ON audit.user_self_service_actions(action_type, created_at DESC);
CREATE INDEX IF NOT EXISTS audit_ussa_resource_idx   ON audit.user_self_service_actions(action_resource_type, action_resource_id)
  WHERE action_resource_id IS NOT NULL;
```

- **Append‑only:** no `DELETE`, no `UPDATE` (except in retention purge — post‑MVP).
- **Retention:** indefinite at MVP. A retention policy (e.g. 24 months sliding window) can be added later via partition by month.
- **Privacy:** `action_payload_summary` is a curated subset of the mutation input (e.g. only `skill_id` + `proficiency` for SKILL_SELF_ASSESS, never free‑text comment in plain).

## 17. FK Closure Note

Every FK in this design targets a table that exists in the same document. The migration order (000001 → 000026) respects dependencies:

- 000003 (`sys_tenancies`) precedes 000004 (`sys_users` references tenancy).
- 000004 (`sys_users`) precedes 000005 (auth references users) and 000006 (profile references users).
- 000009 (`sys_organization_units`) precedes 000011 (`sys_positions` references org unit).
- 000010 (`sys_job_roles`) precedes 000011 (`sys_positions` references job role).
- 000011 (`sys_positions`) precedes 000012, 000014, 000015, 000018, 000019.
- 000022 (visualization) references existing `sys_positions`, `sys_users`, `sys_skills`, `sys_kpi_definitions`, etc.

Validation view `sys.v_canonical_outside_sys` confirms no canonical table escapes `sys`.

## 18. Open Refinements Allowed During Implementation

Within the "target proposal" status, the implementation may refine:

- Column types (`numeric(N,M)` precision, `varchar(N)` length).
- Index names and exact column set (e.g. composite vs single).
- Constraint names.
- Minor field additions (e.g. `notes` text columns).
- Default values where not specified.
- Trigger names.

The implementation may **not** change:

- Table names (canonical or auxiliary).
- Schema placement (`sys` vs `brownfield`/`staging`/`audit`).
- FK direction or target.
- The PIP view design (relational base + view).
- The visualization `sys_visualization_node_layouts` separation.
- The single‑schema canonical rule.

Such changes require re‑opening this deliverable.
