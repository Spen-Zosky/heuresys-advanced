### WS1a — API core  (5 finding)

#### F-007 · 🔵 Low · CSRF origin/referer defense-in-depth uses prefix match (startsWith) — bypassable by suffix-attack origin
- **File**: `apps/api/src/middleware/csrf.ts:33` · **Categoria**: security · **Cross-ref**: NEW · **fp-check**: FALSE_POSITIVE
- **Evidence**: verifyCsrf validates the Origin/Referer with `if (origin && env.ADMIN_ORIGIN && !origin.startsWith(env.ADMIN_ORIGIN))`. `startsWith` on a bare origin has no boundary, so an attacker origin such as `https://app.heuresys.com.evil.com` (or `http://localhost:30000` when ADMIN_ORIGIN=`http://localhost:3000`) satisfies the prefix and passes the check.
- **Impatto**: Weakens the secondary CSRF defense: the Origin/Referer gate no longer reliably pins requests to the admin SPA origin. Not solely exploitable — the primary double-submit token (cookieCsrf===headerCsrf, line 27) is still required — so it is a defense-in-depth erosion, not a standalone CSRF hole.
- **Raccomandazione** (proposta, non applicata): Compare the parsed URL origin for exact equality (`new URL(origin).origin === env.ADMIN_ORIGIN`) instead of `startsWith`, or match against an explicit allowlist of full origins.
- **Verifica (1ª passata)** (CONFIRMED): Evidence reale e in-context: apps/api/src/middleware/csrf.ts:33 fa `!origin.startsWith(env.ADMIN_ORIGIN)` su `req.headers.origin ?? req.headers.referer`. `env.ADMIN_ORIGIN` è `z.url().default("http://localhost:3000")` (apps/api/src/config/env.ts:74) — un URL senza trailing slash garantito, quindi il prefix-match non ha boundary: `http://localhost:30000` o `https://www.heuresys.com.evil.example` passano.
