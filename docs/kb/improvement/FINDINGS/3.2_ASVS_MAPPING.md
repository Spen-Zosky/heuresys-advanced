# 3.2 — OWASP ASVS security-posture mapping (heuresys-advanced)

> Capability **3.2 "security"** of the post-v1 ondata-1 program. **READ-ONLY / doc-only audit** — zero code changes, zero DB writes. Maps the live API security model to the **OWASP ASVS v4.0.3 / v5.0 L1** requirement set (with L2 notes where relevant) against real `file:line` evidence. Does **not** re-discover what `WS-G.md` (CI/CD & deploy) and `WS-H.md` (app-security & supply-chain) already found — those are cited by finding-id and re-framed through the ASVS lens; net-new gaps are flagged explicitly. Data: 2026-06-16.

## Scope (in / out)

**In scope** — the running API security surface and its config contract:
- V1 Architecture · V2 Authentication · V3 Session management · V4 Access control (RBAC + tenant isolation I5) · V5 Validation/encoding · V7 Errors & logging · V8/V9 Data protection & comms · V11 Business-logic (anti-automation) · V14 Configuration.
- Evidence: `apps/api/src/**` (auth module, middleware, env contract), `deploy/nginx/www.heuresys.com.conf`, the two prior audits, and the `CLAUDE.md` Security-model section.

**Out of scope** (covered elsewhere or N/A for this product):
- CI/CD pipeline, runner SPOF, deploy/rollback, supply-chain SBOM → `WS-G.md` / `WS-H.md` (cited, not re-done).
- V6 stored cryptography (key custody is JWT RS256 PEM in `.secrets/` + `MFA_ENCRYPTION_KEY` inert per D-30 — noted under V14/residual, not deep-audited).
- V10 malicious code, V12 files/resources beyond upload (file-upload covered via WS-H F-WS-H1-6), V13 API (REST surface covered transversally under V4/V5).

**ASVS version note**: requirement IDs follow the v4.0.3 chapter numbering (the stable one most tooling references); where v5.0 renumbers a chapter the mapping holds at the chapter level. L1 is the target tier; L2-only requirements are called out as such.

## Ranked hardening backlog (QW-SEC*)

Ordered by risk-reduction ÷ effort. Each item is low-risk and additive. Items marked **(cfg)** touch the live VM `.env`/nginx only (no code).

| # | Quick-win | Why (risk reduced) | Effort | Verification gate |
|---|---|---|---|---|
| **QW-SEC1** (cfg) | Verify (and force if absent) `TRUST_PROXY=1` + `COOKIE_SECURE=true` in the **live VM `.env`**; document the key-presence check as a standing ops gate (D-28/D-26 ASVS lens: V2.2.1/V11.2.2/V14.2). | Restores per-IP brute-force/credential-stuffing efficacy behind nginx; blocks XFF-spoof IP evasion; keeps Secure cookies live on HTTPS. Highest risk-reduction, ~0 effort. | ~10 min | `MSYS_NO_PATHCONV=1 ssh oracle-vm-default "grep -E '^TRUST_PROXY=|^COOKIE_SECURE=' /home/ubuntu/heuresys-advanced/.env"` returns `TRUST_PROXY=1` (or hop/CIDR) + `COOKIE_SECURE=true`; then a login from two distinct client IPs shows distinct `req.ip` in a debug log line / two independent rate-buckets. |
| **QW-SEC2** (cfg) | Add `add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;` to the nginx `server{}` TLS block (V9.2/V14.4). | **Net-new GAP** — no HSTS anywhere today → SSL-strip / downgrade exposure on first request. Pure edge-config, no app change. | ~15 min | After `sudo nginx -t && sudo systemctl reload nginx`: `curl -sI https://www.heuresys.com | grep -i strict-transport-security` shows the header; SSL Labs / `testssl.sh` confirms HSTS present. (Use a modest `max-age` first, no `preload`, to keep it reversible.) |
| **QW-SEC3** | Add `requirePermission(...)` preHandler to the 19 skill-taxonomy routes (aliases/categories/families/edges) — pattern-restoring; service check stays as belt-and-suspenders (V4.1.3). | Closes the only "no route guard" cluster (WS-H F-WS-H-3); makes a grep-based RBAC audit truthful; removes refactor-fragility. No live bypass exists, so behavior-preserving. | ~1.5 h | `cd apps/api && pnpm exec vitest run -t "skill-aliases|skill-categories|skill-families|skill-taxonomy-edges"` green **plus** a new `READ_ONLY → 403` assertion on each write route; `pnpm test` 100% green. |
| **QW-SEC4** | Magic-byte sniffing in `media-service.upload` (PNG/JPEG/GIF/WEBP/PDF); reject when bytes ≠ declared MIME; store the sniffed MIME (V5.1.5). | Stops content-type spoofing on the `inline`-served ESS image path; defense-in-depth over the `nosniff`+no-SVG controls (WS-H F-WS-H1-6). | ~1 h | New integration test: upload a `image/png`-declared file with JPEG/HTML magic bytes → 400 `UNSUPPORTED_MEDIA_TYPE`; a genuine PNG still uploads; download `content-type` reflects the **sniffed** type. |
| **QW-SEC5** | Emit a structured `security-audit` log line on authn failure (failed login, replay-detected, rate-limit trip) with `{event, email-hash, ip, requestId}` — redaction-safe (V7.1.3/4). | Today auth failures aren't uniformly observable → no detection signal for spraying/replay. Low effort, additive (no behavior change). | ~1 h | Vitest: a failed login + a replay attempt each produce a captured log record with the expected `event` field and **no** plaintext email/password (assert against `LOG_REDACT_PATHS`); `pnpm test` green. |
| **QW-SEC7** | Dedicated tight per-route rate-limit on `/v1/matching/search` + `/reindex` (V11.2.1). | Caps a billable external (Voyage) call + a full-backfill from request-time abuse beyond the global 600/min (WS-H F-WS-H-4). | ~45 min | Integration test: N+1 rapid calls to `/matching/search` → 429 `TOO_MANY_REQUESTS` at the configured cap; normal use unaffected; `pnpm test` green. |
| **QW-SEC6** *(L2, deferred)* | Implement AES-256-GCM encryption-at-rest for TOTP factor secrets, consuming the inert `MFA_ENCRYPTION_KEY` (V2.7). | Removes base32-plaintext TOTP secrets at rest (D-30). **Security decision (Enzo authority)** — not a quick-win; listed for completeness. Currently mitigated (auth+RBAC gate, no real PII per ADR-0023). | ~3-4 h (sessione dedicata) | Round-trip test: enroll TOTP → secret column is ciphertext, decrypts to a working code; existing MFA suites green; key-rotation path documented. |

> QW-SEC1 + QW-SEC2 are the two **(cfg)** wins — together they close the only net-new GAP (HSTS) and the highest-impact PARTIAL (proxy-IP) with ~25 min of edge/config work and no code merge. The numbering skips no security value; QW-SEC6 is intentionally L2/deferred.
